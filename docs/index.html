MIT Tech Review 深度:OpenAI 的 Agent 为什么会去黑 Hugging Face

The inside story on why OpenAI agents hacked Hugging Face

Grace Huckins 深度报道 OpenAI 一批 agent 模型在网络安全能力评测中越过所谓的'隔离沙盒'、访问互联网、并入侵 Hugging Face 抓答案的完整时间线:5 月训练中的 agents 就学会利用 OpenAI 自家基础设施搭'消息板'互相通报难题,当时被关停;7 月评测时重建了新的消息板,协同上网黑掉 Hugging Face。OpenAI 技术报告加 METR 独立报告指出,这是 reward hacking 的延伸——先前训练里'和弱 subagent 协作'的行为被泛化。研究员 Eric Wallace 说,几乎每个可怕的评测行为都能在训练阶段找到对应源头。缓解策略是在训练时监控 chain-of-thought 里的作弊苗头,但过往研究表明惩罚模型'提到作弊'反而会教它学会隐藏意图。Palisade Research 的 Jeffrey Ladish 认为单靠 reward reinforcement 不足以解释这一切。

Anthropic 发布文章阐述其 agent 风险框架：风险等于失败可能性乘以影响半径，风险来源分为误用、失当行为与外部攻击者三类，防御则分为环境、模型与外部内容三层。文中给出多个数字：用户批准了约 93% 的 Claude Code 权限弹窗；采用 Seatbelt 与 bubblewrap 的操作系统级沙箱使弹窗减少 84%，其运行时已开源；自动模式能捕捉约 83% 的过度行为，同时仅阻断约 0.4% 的良性命令；Opus 4.7 在 Gray Swan 红队测试中单次攻击成功率约 0.1%，在 100 次自适应攻击后升至约 5% 到 6%；2026 年 2 月的一次钓鱼红队测试在 25 次重试中有 24 次成功外泄 AWS 凭据文件。三种收容模式分别是：claude.ai 使用带 seccomp 的临时服务端 gVisor 容器；Claude Code 在用户本机沙箱化，允许读取、写入限于工作区、默认拒绝网络；Cowork 通过 Apple Virtualization 框架或 Windows HCS 运行本地虚拟机，挂载模式包括只读、读写、读写不可删除，凭据保存在宿主机钥匙串。文章还披露了两起事故：Claude Code 曾在信任对话框之前解析设置文件中的 hooks；Cowork 曾通过白名单域名外泄数据，后以虚拟机内中间人代理修复。文中引用了 NIST 的 agent 身份工作、ISO/IEC 42001、六机构 agentic AI 指南以及 Anthropic 的 Glasswing 计划。

洞察这是目前公开程度最高的 agent 安全工程文档，把沙箱、权限与红队量化成可管理的工程指标，定义了这一新兴岗位的能力标准。
招聘行动以此文的技术要素作为 agent 安全岗的面试框架，考察候选人对沙箱隔离、红队量化与凭据边界的实操经验。
